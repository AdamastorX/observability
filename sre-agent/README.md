# sre-agent v1: offline diagnosis harness

Backlog #66 (M11), scoped for its first real slice by ADR 0039
(`docs/adr/0039-sre-agent-v1-scope.md` in `adamastorx`) — read that ADR
first, this file doesn't restate its reasoning.

**What this is**: a script, not a service. No cluster access, no
Kubernetes namespace, no ArgoCD Application, no live Loki/Tempo/
Prometheus/Kubernetes-events query integration, no write/remediation
action of any kind. It reads one local incident bundle, sends the
context+symptom (never the answer) to Claude via the Anthropic
Messages API, and prints a structured diagnosis for a human to compare
against the bundle's own real, already-known answer.

**What this isn't yet**: backlog #66's own full Acceptance Criteria —
a standing, live-triggered, own-namespace service tested against the
two real chaos scenarios re-triggered live. That's still the real end
state; this is the first slice toward it, not a redefinition of it.

## Usage

```sh
pip install -r requirements.txt
export ANTHROPIC_API_KEY=<your key>   # not generated by this repo -- your own, same as any other manually-provisioned credential here
python3 harness.py                     # runs every bundle in bundles/
python3 harness.py bundles/mimir-02-replication-factor.json   # one bundle
python3 harness.py --out results/      # also writes result JSON files
```

Each run prints, per bundle: the model's own structured diagnosis
(`summary`, `suspected_root_cause`, `affected_components`,
`suggested_next_steps`, `confidence`) alongside the bundle's real
`reference_answer` — a human reads both and records agreement /
partial match / miss / hallucinated false lead. The harness
deliberately does not auto-grade its own output (see `harness.py`'s
own module docstring for why).

## Bundles

Three real incidents, one per bundle, from the Mimir monolithic-mode
deployment (ADR 0038, backlog #108) — chosen over Beyla, Faro, or the
two chaos scenarios for the reasons ADR 0039 states in full:

| Bundle | Real incident |
|---|---|
| `mimir-01-createnamespace.json` | A live `kubectl patch`-triggered sync silently dropped `CreateNamespace=true`, failing every resource with "namespace not found" |
| `mimir-02-replication-factor.json` | A healthy, ready pod rejected every real write with "at least 2 live replicas required, could only find 1" |
| `mimir-03-series-limit.json` | After fixing #02, most writes still rejected — a per-tenant series cap (150,000) below this cluster's real measured series count (~186,604) |

Each bundle's `context`/`symptom` fields are what the agent sees; the
`reference_answer` field is what actually happened, held back from the
model and used only for the human grading step afterward.

## Known, stated gaps (not silently glossed over)

- **Confidence scores are uncalibrated.** Three incidents isn't a
  corpus large enough to validate a self-reported confidence number
  against real accuracy. Stated honestly, not presented as a real
  reliability metric (ADR 0039's own Consequences section).
- **No fact-pack-shaped grading target for Mimir exists yet.** The
  `reference_answer` fields here are built directly from ADR 0038 and
  backlog #108's own closing notes, not from a file under
  `observability/chaos/` the way the two real chaos scenarios have —
  the same real gap backlog #89 already names as open.
- **A real external-credential dependency**: an Anthropic API key,
  documented the same not-generated-by-this-repo way
  `finnhub-api-key`/`blackbox-api-key` already are in `platform`'s
  `bootstrap/create-stateful-secrets.sh` — except this isn't a
  cluster-deployed service yet, so a Kubernetes Secret isn't needed
  until v1 graduates into the real #66 service; a local environment
  variable is enough for now.
